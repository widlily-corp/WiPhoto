# WiPhoto (v3.0.0)

Профессиональный, высокопроизводительный менеджер и редактор фотографий для десктопа. Построен на базе **Tauri v2**, **Rust** (бэкенд для тяжелых операций) и **Vanilla JS / CSS** (фронтенд с дизайн-системой Refined Minimal).

---

## 🚀 Быстрый старт

### Требования к окружению
Для запуска проекта вам понадобятся:
1. **Node.js** (LTS-версия рекомендуемая)
2. **Rust & Cargo** (инструментарий Rust для сборки бэкенда)
3. Дополнительные зависимости Tauri для вашей операционной системы (подробнее см. на [tauri.app](https://tauri.app/start/prerequisites/)).

### Установка зависимостей
Запустите команду в корневой директории проекта:
```bash
npm install
```

### Запуск в режиме разработки (Hot Reload)
Для запуска приложения с автоматической перезагрузкой при изменении кода выполните:
```bash
npx tauri dev
```
или:
```bash
npm run tauri dev
```

### Сборка финального дистрибутива
Для сборки оптимизированного production-пакета под текущую платформу:
```bash
npx tauri build
```

## 🛠️ Архитектура и Оптимизации

### 1. Высокопроизводительный рендеринг (Virtual Grid)
Для корректной работы с библиотеками на 10,000+ фотографий используется кастомный движок виртуализации [virtualgrid.js](file:///c:/Users/Widlily/Documents/projects/wiphoto/src/js/virtualgrid.js):
* Рендерит только те карточки, которые находятся в видимой области экрана (+ небольшой буфер сверху и снизу).
* Вместо полной очистки сетки через `innerHTML = ''`, используется **DOM diffing** алгоритм, который добавляет, удаляет или перемещает только карточки, пересекающие границы видимости при прокрутке.

### 2. Централизованное логирование (Logger)
Все ошибки и предупреждения фронтенда обрабатываются через фасад логирования [logger.js](file:///c:/Users/Widlily/Documents/projects/wiphoto/src/js/logger.js):
* Сообщения разбиты по уровням: `trace`, `debug`, `info`, `warn`, `error`.
* Логи фронтенда автоматически транслируются в стандартный вывод бэкенда Rust через Tauri IPC-мост (`API.logJs`).
* Глобальные ошибки окна (`window.onerror`) и необработанные промисы (`window.onunhandledrejection`) перехватываются логгером.

### 3. Обработка изображений на Rust
Тяжелые операции (расчет хэшей дубликатов, чтение EXIF, генерация миниатюр RAW-файлов с поиском встроенных JPEG-превью, кадрирование и применение эффектов редактора) вынесены в Rust. Фронтенд взаимодействует с ними асинхронно через Tauri Commands.

## 🎨 Стандарты кодирования (Для разработчиков)

### Коммиты в Git
Мы используем стандарт **Conventional Commits** для ведения истории изменений:
* `feat(...)` — новые функции / компоненты.
* `fix(...)` — исправление багов.
* `style(...)` — правки стилей, отступов, тем.
* `perf(...)` — оптимизации производительности.
* `refactor(...)` — рефакторинг кода без изменения логики.

### Фронтенд правила
* Не используйте инлайн-стили (`style="..."`) в разметке HTML. Все новые элементы должны получать стили через классы в `src/styles/components.css` или специализированных стилях.
* Ошибки в асинхронных операциях должны логгироваться явно через `Logger.error(...)` или `Logger.warn(...)`, пустые конструкции `catch {}` запрещены.
