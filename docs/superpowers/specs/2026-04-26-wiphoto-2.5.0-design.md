# WiPhoto 2.5.0 — Design / Spec

**Дата:** 2026-04-26
**Текущая версия:** 2.4.4
**Целевая версия:** 2.5.0 (minor)
**Scope:** L без светлой темы

## Цели релиза

1. Закрыть структурные слабости (god-controller, PyQt в core, bare excepts).
2. Поднять отзывчивость на больших библиотеках (10K+ фото): кэши, async, backpressure, lazy imports.
3. Добавить недостающие pro-фичи: command palette, manual keywords, white balance picker, undo/redo шорткаты.
4. Стабильный выход без зомби-потоков.

Не делаем: светлая тема, GPU, cloud, panorama/HDR, локализация EN, lens profiles.

## Этап 1. Performance core

### 1.1 LRU-кэш превью QPixmap
- **Файл:** `views/main_window.py` (поле `_preview_cache`, ~стр. 56).
- **Что:** заменить dict + хардкод-лимит 5 на `OrderedDict` с лимитом по сумме `QPixmap.sizeInBytes()`. Дефолт 256 МБ, настраивается в `core/settings_manager.py`.
- **API:** маленький класс `PixmapLRUCache(max_bytes: int)` в `views/_pixmap_cache.py` с методами `get/put/clear`.
- **Критерий:** при выделении 1000 фото память не растёт линейно, удерживается в районе лимита.

### 1.2 Кэш бейджей и масштабированных миниатюр в делегате
- **Файл:** `views/thumbnail_delegate.py`.
- **Что:** кэшировать готовые QPixmap для:
  - звёзд рейтинга (по числу 0..5),
  - индикаторов RAW/Video/AI/Pick/Reject,
  - масштабированных thumbnail под текущий zoom (ключ = `(path, target_size)`).
- **API:** статические OrderedDict-кэши на классе делегата, лимиты ограниченные (например 64 для бейджей, 512 для миниатюр).
- **Критерий:** профайл `paint()` не вызывает `Pixmap.scaled()` при повторных перерисовках.

### 1.3 Async EXIF и prefetch
- **Файл:** `core/metadata_reader.py` + `views/main_window.py`.
- **Что:**
  - Вынести запрос к ExifTool daemon в `MetadataReaderWorker(QThread)` с очередью `queue.Queue`. UI шлёт пути → сигнал `metadata_ready(path, dict)`.
  - Prefetch: при выделении фото — запросить EXIF + превью для ±N соседей на idle.
- **Критерий:** 5-секундный таймаут ExifTool не блокирует UI; навигация по галерее остаётся гладкой даже на медленных дисках.

### 1.4 Backpressure в file_scanner
- **Файл:** `core/file_scanner.py:75-86`.
- **Что:** заменить eager submit всех чанков на bounded submission через `Semaphore(cpu_count*2)` или `as_completed` с динамическим пополнением.
- **Критерий:** на папке 50K файлов память воркеров ограничена, нет OOM.

### 1.5 Lazy imports
- **Файлы:** `main.py`, `controllers/photo_view_controller.py`, `controllers/app_controller.py`, `views/editor_widget.py`.
- **Что:** перенести импорты `rawpy`, `cv2`, `imagehash`, `pillow_heif`, `core.analyzer`, `core.ai_worker`, `core.advanced_duplicate_finder` внутрь функций, использующих их. На старте грузим только Qt + минимум.
- **Критерий:** `python main.py` показывает welcome-окно за <1.5 c (на референсной машине). Nuitka-сборка корректно подхватывает зависимости (проверка в build script — `--include-package` уже стоят).

## Этап 2. Архитектура

### 2.1 Декомпозиция photo_view_controller
- **Файл:** `controllers/photo_view_controller.py` (1224 строки).
- **Что:** создать `controllers/services/`:
  - `duplicate_service.py` — поиск дубликатов, ранжирование.
  - `ai_analysis_service.py` — лица, животные, качество.
  - `file_ops_service.py` — move/copy/delete/rename, корзина.
  - `filter_sort_service.py` — фильтры, сортировка, smart-collections.
- **Контроллер** — тонкий координатор, держит ссылки на сервисы и пробрасывает сигналы. Цель — ≤400 строк.
- **Критерий:** все существующие функции работают идентично; smoke-test покрывает scan → filter → duplicate → AI → file op → editor.

### 2.2 Кастомные исключения
- **Новый файл:** `core/exceptions.py`.
- **Иерархия:**
  ```
  WiPhotoError(Exception)
    PhotoScanError
    RawDecodeError
    ExifReadError
    MetadataWriteError
    DuplicateSearchError
    AIAnalysisError
  ```
- **Что:** заменить ~20 `except Exception` в `controllers/`, `core/file_scanner.py`, `core/metadata_reader.py`, `core/analyzer.py` на типизированные. Сообщения в QMessageBox — конкретные.
- **Критерий:** в логах видно тип исключения, пользователь видит понятную причину.

### 2.3 Type hints в hot paths
- **Файлы:** `controllers/photo_view_controller.py`, `views/main_window.py`, `views/gallery_widget.py`, новые сервисы.
- **Что:** добавить аннотации публичным методам и Qt-слотам (`list[ImageInfo]`, `Path`, `str | None` и т.д.). Без mypy в CI — только улучшение читаемости.

### 2.4 Lifecycle потоков и диалогов
- **Файл:** `controllers/app_controller.py` + новый `controllers/thread_registry.py`.
- **Что:** регистрировать все долгоживущие QThread (scanner, AI, duplicate, metadata reader). На `app.aboutToQuit` — `quit()` + `wait(2000)` с принудительным `terminate()` если истёк таймаут. Сохранить совместимость с `cleanup_exiftool`.
- **Критерий:** Ctrl+C / закрытие окна не оставляет зомби-процессов и не падает с RuntimeError.

## Этап 3. UX и фичи

### 3.1 Undo/Redo шорткаты
- **Файл:** `views/editor_widget.py`, `views/history_tree_widget.py`.
- **Что:** `QShortcut(QKeySequence.StandardKey.Undo)` и `Redo` (`Ctrl+Z` / `Ctrl+Shift+Z`). Пункты в меню Edit главного окна. Связать с существующим механизмом истории (history tree уже есть).
- **Критерий:** в редакторе шорткаты откатывают/повторяют последнее действие.

### 3.2 Command palette
- **Новый файл:** `views/command_palette.py`.
- **Что:** модальный диалог по `Ctrl+K`, `QLineEdit` + `QListView` с `QSortFilterProxyModel` (fuzzy через простую подстроку без отдельной библиотеки). Реестр команд `core/command_registry.py` — таблица `(id, title, shortcut, callback, category)`. Заполняется на старте main_window'ом.
- **Команды (минимум):** Открыть папку, Сканировать, Поиск дубликатов, Пакетный экспорт, Slideshow, Rate 1..5, Pick/Reject, Полный экран, Открыть настройки.
- **Критерий:** Ctrl+K → ввод "dup" → Enter запускает поиск дубликатов.

### 3.3 Manual keyword/tag UI
- **Новые файлы:** `views/keyword_panel.py`, `core/tag_store.py`.
- **Что:**
  - Панель в правой колонке (после metadata): список тегов выделенного фото, ввод новых, удаление.
  - Хранение в EXIF `XMP-dc:Subject` через ExifTool (write через `metadata_reader`).
  - В `models/image_model.py` уже есть поле `tags` — переиспользовать. Различить user vs AI tags через префикс или отдельное поле `user_tags` (новое в `ImageInfo`).
  - Фильтр по тегам в левой колонке — добавить как новый источник (помимо smart collections).
- **Критерий:** теги сохраняются в файл, видны в Lightroom/digiKam, фильтр по тегу показывает только помеченные фото.

### 3.4 White balance picker
- **Новый файл:** `core/editing/tool_white_balance.py`.
- **Что:** инструмент в стиле существующих (`base_tool.py`), eyedropper по нейтральной точке. По выбранному пикселю — рассчитать корректировку temperature/tint, применить через существующий image_processor.
- **UI:** кнопка/иконка в редакторе, курсор-пипетка, клик по изображению.
- **Критерий:** клик по нейтральной поверхности (стена, лист бумаги) приводит к видимой коррекции цветовой температуры.

### 3.5 Документирование и расширение шорткатов галереи
- **Файл:** `views/gallery_widget.py`, README или новый `docs/shortcuts.md`.
- **Что:**
  - Добавить: `P` (pick), `X` (reject), `Ctrl+D` (поиск дубликатов выделенного), `Space` (toggle fullscreen preview), `[`/`]` (prev/next).
  - Описать в `docs/shortcuts.md` все действующие.
- **Критерий:** все шорткаты работают и видны в command palette.

## Риски и mitigation

| ID | Риск | Mitigation |
|----|------|-----------|
| R1 | Декомпозиция контроллера ломает сигналы | Рефакторить сервис за сервисом, smoke-test после каждого |
| R2 | Lazy imports ломают Nuitka | Проверить сборку до тега, при необходимости оставить eager в проблемных местах |
| R3 | Новые QThread без cleanup | Строгая регистрация через `thread_registry` |
| R4 | Запись XMP может конфликтовать с RAW (sidecar) | Для RAW писать в `.xmp` sidecar, не в сам файл |
| R5 | LRU-кэш через `sizeInBytes()` может быть неточен на разных Qt-бекендах | Fallback на `width*height*depth/8` |
